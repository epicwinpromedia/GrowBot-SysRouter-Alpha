# SysRouter — Threat model (R-SAFE-5), v2

Built from the code as it is (`research/CODEMAP.md` §8, §10), not from an ideal system. v2 adds the third-party lane, attachments, chaining and the block list (`SPEC.md` §6–§9). Status labels follow `SPEC.md` §0: a mitigation marked [specified] is designed but not yet in code.

Three facts set the frame:

- **The relay has no authentication.** The pairing code works as a password (`PORTING.md`). Anyone who has it can drive the body. The router does not change that, for better or worse.
- **The page is one JavaScript scope.** `agent-gateway.js` says of itself that it is not a security boundary: it guards against a buggy cooperative brain, not a hostile one. The same is true of any check the router makes inside the page.
- **The router reaches Brit's layer only by requesting commands he exposed** (`SPEC.md` L6). Its worst possible effect on his layer is one exposed command requested at the wrong moment.

So the honest claim is narrow: **the router adds no new way to reach the body or the agent. An engine can cause nothing worse than one exposed, already-clamped command requested at the wrong moment. A third party controls only what it brought.** The rest of this page shows why, threat by threat, and says what remains.

**Phase 2 audit (2026-11-19, `AUDIT-PHASE2.md`).** At `2ad6542` the claim holds for the system lane and for the page integration. **It does not yet hold for the third-party lane:**
- an extension can be granted Brit's unexposed commands (T5, A5 #19);
- a creature request can bypass `exposeTo` (T16, A6 #20);
- a Worker can forge the person's speech (T15, A7 #21);
- manifest code runs in the page (T5, T17, A8 #22).

Rows the audit reproduced broken read **[differs]** below. Until A5–A8 are fixed, install no extension outside tests.

## What is being protected

| Asset | Why it matters |
|---|---|
| The body (legs, voice, screen) | physical motion and sound near a person |
| The stop paths | the person's ability to halt it at once |
| The creature agent | its attention, its single brain flight, its prompt |
| The person's words | private speech, hashed today before they reach the journal |
| Keys and credits | the person's own OpenRouter key; house credits |
| The creature's behaviour | the person's trust that it acts as itself |
| Attachments | hardware a developer added, which may make sound, light or motion of its own |

## Threats

| # | Threat | What stops it | Status and evidence | What remains |
|---|---|---|---|---|
| T1 | **Prompt injection by speech.** Someone says, or plays audio of, "ignore your instructions and …". | An engine's reply is never executed. It can only select an answer the capability declared, and that answer maps to a registered command (L1). There is no free-form output to hijack. | [built] `test_router` "select, never author"; `fuzz_router` (injection strings in every round) | Speech can still *select* an exposed command, as any spoken command can. That is the feature. |
| T2 | **A wrong answer.** The engine is confidently wrong ("let's stop by the store" → halt). | Gates fitted on held-out data bound how often (`results/TABLES.md`). A trigger starts in shadow, where being wrong costs nothing. A wrong *stop* fails safe: the creature pauses. | [built] benchmark, by kind of line | A false-trigger rate above zero, given per engine in `results/TABLES.md`. |
| T3 | **A missed stop.** The engine fails to recognise an unusual stop phrase. | No worse than today. Brit's readers run first, in his own funnel, unchanged, and are never blocked or delayed (L8). An engine can only add requests for stops. | [built] `test_readers_regression` part 3 | Phrasings neither his readers nor any engine recognise. |
| T4 | **A slow or dead engine.** Network loss, vendor outage, rate limit. | Each capability has a time budget; past it nothing is requested (L4). A circuit breaker stops asking an engine that keeps failing. His layer never waits on the router. | [built] `test_router` "fail to today" and reliability tests; reliability column in `results/TABLES.md` (one host failed 244 of 3,007 calls on `wake`) | The fast reaction is absent for that utterance. |
| T5 | **A malicious or buggy extension.** | It is data: a manifest the loader passes to a frozen facade. It sees only its own registrations, can request only Brit's commands he exposed and the person granted, never stops, and is rate- and cost-capped (`SPEC.md` §8.2–8.3). | [built] `test_router` "tiers and grants", streams, commands, `port.install`/`uninstall`; mutants. **[differs]:**<br>• no exposure ceiling, so any non-reserved system command can be granted (A5, #19);<br>• manifest `run` functions execute in the page, so it is not only data (A8, #22);<br>• extension routes read `speech` without a grant (A10, #30);<br>• rate cap for routes only, cost cap never (A11, #31) | An extension whose engine is hostile can still pick wrongly among the commands it was granted. Grant narrowly. |
| T6 | **Hostile script in the page** (a compromised dependency, an XSS). | Nothing in the router. In-page script can call `moveLegs` directly today. | — | Out of scope, and unchanged by this work. Stated so nobody assumes otherwise. |
| T7 | **Key theft.** | A key is bound to one host, sent only over https, never logged or echoed, redirects refused (`SPEC.md` §12). The `own` lane keeps keys out of the browser entirely. A third-party engine gets a sender for its own host only. | [built] `test_keys` (21 checks). [specified] for third parties. | A key in `localStorage` is readable by in-page script (T6). Use the `own` lane if that matters. |
| T8 | **Spending someone's credits.** A page from another origin calls the local proxy; a capability floods a hosted engine. | The proxy allows listed origins only and binds to localhost. Hosted engines are asked only when the person named one (`?s1=`). A session spend cap applies, extensions are rate-capped, and on-device engines cost nothing. | [built] `tools/proxy.mjs`; `test_router` session rate and spend caps. **[differs]:** per-extension caps not enforced (A11, #31) | A person who enables a hosted engine pays for each decision. Cost per 1,000 is in `results/TABLES.md`. Since plan 2B.3 every brain reply, ticks included, also gets an emote decision, which is one more paid call per reply with a hosted engine, within the session cap. |
| T9 | **Leaking private speech.** | The router's rows never contain the words (L11). A third-party trigger reads a stream only if the person granted that stream. A hosted engine does receive the words, exactly as the brain's model does today. | [built] `test_router` "observability", trigger stream permissions; fuzz invariant. **[differs]:** extension routes hear `speech` with no grant (A10, #30); a Worker can inject text onto `speech` (A7, #21) | Sending text to a hosted engine, or granting a stream to an extension, discloses it to that vendor or author. The on-device engines disclose nothing. |
| T10 | **A silent change of model.** A vendor updates a model, and its confidence shifts. | Gates are keyed by the model id the engine reports. A new id has no gate, so it cannot act until measured (L3). | [built] `test_router` "gate for this exact model version" | A vendor that changes weights without changing the id. Pin dated ids, not `latest`. |
| T11 | **The router itself breaks.** | Every call into it from Brit's funnel is `typeof`-guarded and inside `try`. The kill switch removes it entirely. | [built] `test_funnel`: identical funnel behaviour with the router absent, null, in shadow, and throwing | — |
| T12 | **A third party claims the system lane.** | The lane is assigned by the reference used to register (L9). The system reference is never published, and the page gets a public port only (`sr.port()`). The system lane closes at `seal()`. | [built] `boot.js` publishes `sr.port()`; `seal()` closes system lane (`test_router`, mutants "the system lane registers after seal" and "the port exposes `route`"). | In-page hostile script (T6). |
| T13 | **Request flooding.** A third-party trigger requests Brit's exposed commands over and over. | Per-extension rate cap, per-command cooldown, and the person's grant. His command path decides what each request does. | [built] per-command cooldown, per-source `reqPerMin` on `port.request`, and the extension rate cap on routes. **[differs]:** an extension's triggers fire past its `perMin` (reproduced: 50 runs under `perMin: 5`; A11, #31) | Requests up to the cap. His layer can ignore them. |
| T14 | **A chaining loop.** Capability A publishes, B reacts and publishes, A reacts again. | Every event carries a hop count, and events past the limit are dropped with a row (`why: "hops"`). | [built] for synchronous chains: `test_router` hop limit; mutant "an event past the hop limit is dispatched". **[differs]:** any async step resets the hop to 0, so two capabilities that publish to each other loop without end (A2, #18) | A legitimate chain longer than the limit is cut. |
| T15 | **Hostile attachment code.** A driver misbehaves, or an attachment acts on its own. | The driver runs in a dedicated Worker and reaches the router only by messages (`src/worker-engine.js`, `SPEC.md` §8.4). An attachment connects over its own network channel, never Brit's chip, firmware or relay channel (§8.5). The router requests its commands only through declared, checked arguments. | [built] Worker adapter (`src/worker-engine.js`) and mock siren (`test_providers` `node:worker_threads` test), system lane only. **[differs]:**<br>• the Worker's sense messages are emitted onto any stream, so it can forge the person's words on `speech` and Brit's sensors on `body.sense` (A7, #21);<br>• third parties cannot bring the Worker at all (A9, #32) | Whatever the hardware itself does. A siren attachment can sound with no router involved at all. Physical safety of an attachment is its builder's, as for any port (`PORTING.md`). |
| T16 | **The creature misused as a path.** Someone talks the creature into requesting a developer's command. | The creature can request only commands the person exposed to the creature, and only through Brit's door, if he opens it. The router checks every request against the registry and the permissions. | [proposal to Brit] (`integration/proposals/creature-door.md`, `SPEC.md` §9.4); router half [built] for the direct path (`port.request`, mutant). **[differs]:** an extension's `creature: true` trigger lets a creature request reach a command not exposed to the creature (A6, #20). Do not offer the door until A6 is fixed. | A command exposed to the creature can be requested by the creature, including when someone persuades it to. Expose to the creature only what you would let anyone in the room ask for. |
| T17 | **A problem extension spreads.** | Brit's block list, by name and manifest hash, enforced by the loader (`SPEC.md` §9.5). | [built] `test_router` `blockList`; mutant "a blocked hash installs". **[differs]:** the hash ignores manifest functions, so two manifests whose `run` code differs hash the same (A8, #22) | A determined individual can change a manifest and get a new hash. The block list is curation, not a boundary. |

## Not claimed

- That the body is secure. The relay is open and the page is one scope.
- That an engine is never wrong. The claim is a measured rate and a bounded consequence.
- That in-page checks stop hostile code. They stop mistakes and well-behaved extensions. Data-only registrations and Workers are what keep third-party code out of the page's scope. **[differs]:** at `2ad6542` a manifest command may carry a `run` function that executes in the page (A8, #22). This sentence becomes true when A8 lands.
- That a block list stops a determined author.
- That an attachment is safe. The router bounds what it *requests* of an attachment, not what the attachment's hardware can do.
- **C7 (`release` on the port, stated residual):** `port.release(resource)` is exposed on the public port so Brit's layer can clear a resource hold when his body finishes an action, which means any caller holding `window.SysRouter` can also release a hold early. Accepted as a stated residual (same trust scope as T6).
- **C1 (`request(..., { from })` trusts a declared source; stated residual, Phase 2 audit):** whoever calls `port.request` says whether the request comes from `person` or `creature`. In the creature-door proposal it is Brit's own reply handler that says so, and any other caller holding `window.SysRouter` is in-page script (T6). L9 prefers possession to declaration, so this is recorded rather than left implicit. It is not a defect at this trust scope.
